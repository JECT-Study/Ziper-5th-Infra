# 0006 공개 readiness의 제한된 준비 시간과 오류 분류

- 상태: 채택 — 로컬 검증 대상, 새 정책의 운영 배포 미실행
- 날짜: 2026-11-06

## 배경

Server 실행 42222169766은 이미지 전달과 앱 내부 readiness를 통과했지만 공개 검사에서 HTTP 530으로 실패했다. cloudflared Started와 검사 시작의 차이는 약 0.443초다. 상세 오류가 없어 기동 지연은 가설이며 현재 정상 응답으로 당시 원인을 확정하지 않는다. 별도로 Accept 없이 기본 vendor JSON을 받으면서 application/json만 허용한 검사기 문제를 재현했다. 경로 오류의 증거는 없다.

## 결정

계약 검사와 오류 분류는 Server의 기존 verify-public-health.py에 둔다. Infra는 그 CLI에 요청 10초, 전체 준비 시간 180초, 일시적 실패 후 5초, 정상 검사 쌍 사이 10초와 연속 정상 3회를 명시한다. 기존 기본 CLI는 첫 오류에 실패하며 준비 시간 옵션을 지정할 때만 재시도한다. 두 경로는 /livez와 /readyz를 유지한다.

HTTP 502·503·504·520~524·530, 연결 거부·중단·재설정·도달 불가·시간 초과와 일시적 DNS 오류만 재시도한다. 인증·리다이렉트·TLS 검증·영구 DNS 오류와 응답 계약 위반은 즉시 실패한다. 일시적 실패가 끼면 연속 정상 횟수를 초기화하며, 한도에 도달하면 실패한다. 재시도는 읽기 헬스 요청에만 적용하고 배포 명령을 다시 실행하지 않는다.

Accept: application/json으로 협상하고 기존 User-Agent와 엄격한 JSON·캐시·본문 조건을 유지한다. 실패 경로·HTTP 상태·시도·경과 시간·정적 이유를 artifact로 보존한다. 응답 본문과 비밀은 저장하지 않으며 Cloudflare 상세 코드는 추측·추출하지 않는다. 기존 광범위한 예외 재시도 wrapper는 삭제한다.

Infra main의 성공한 실제 SHA를 확인한 뒤 Server 구현과 workflow의 두 참조를 함께 갱신한다. 고정된 과거 Infra를 수정한 것으로 오인하지 않는다. source와 Infra의 동일 SHA main CI 검증과 수동 배포 조건은 유지한다.

## 대안

- 무조건 sleep: 준비 완료를 확인하지 못하고 영구 오류도 숨긴다.
- 모든 예외 재시도: 인증·미디어 타입 같은 계약 오류의 진단을 늦추므로 제외한다.
- 모든 JSON 미디어 타입 허용: 서버가 application/json 협상을 지원하므로 범위를 넓히지 않는다.
- deploy.sh에서 공개 검사: 호스트 내부와 외부 runner 검증을 혼동하지 않도록 기존 외부 검사 단계에 둔다.

## 영향과 한계

180초에는 요청·본문 읽기·대기 시간이 포함되며 CLI 준비와 결과 저장은 제외한다. POSIX 타이머를 지원하는 Linux runner와 macOS에서 실행한다. 준비 시간은 일시적 530을 흡수할 수 있지만 530의 과거 원인을 증명하지 않는다. 검사 성공은 Cloud Run failover·600초 목표·장기 uptime·Discord 성공 알림을 증명하지 않는다.

Linux workflow는 `timeout --signal=KILL 180s`로 검사 프로세스 전체에도 상한을 적용한다. Python 신호 처리가 지연되는 경우도 운영 단계가 계속 대기하지 않는다. 검사 JSON은 요청 전후 원자적으로 갱신하므로 강제 종료 시 마지막 경로·시도와 미수신 상태를 확인할 수 있다. 이 경우 `termination: running`은 성공을 뜻하지 않으며 Actions의 강제 종료 결과와 함께 실패로 판정한다.
